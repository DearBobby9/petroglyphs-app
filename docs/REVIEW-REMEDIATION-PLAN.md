## 1. 目标、来源与维护规则

目标：让同一份需求从画布编辑、图文提交、创建聊天、执行到恢复保持连续。先保护用户数据和请求，再改善操作与阅读，最后扩展能力。

来源：[完整 review](https://chatgpt.com/share/6ad2e667-73dc-83e9-bb95-7c7c6fd637a8)及本聊天逐项讨论。

- MCP：`4e3d3f916932be8035a17abf9276f75069da4732`。
- 第一轮 review 记为 R1，第二轮 UI/UX review 记为 R2。编号用于保留原始覆盖关系，不表示新的优先级。
- mini 本轮执行了生产构建、162 项 MCP 测试、125 项 App 单元/模型测试及 4 项 iPad UI 场景；新增回归记录修复前失败与修复后通过。原 review 不作为新版本的运行证明。
- iPad Simulator 与本机 Desktop/bridge 的证据分别见 [模拟器报告](MINI-SIMULATOR-ACCEPTANCE-2026-10-16.md)和[运行报告](MINI-RUNTIME-2026-10-16.md)。实体 Pencil、硬件键盘、VoiceOver 与主 Mac 实际离线仍未执行。

## 2. 优先级定义

这里的 P0–P3 是本项目整改优先级，不是线上事故等级。原 review 的 P1/P2 已按影响重新排序。

| 优先级 | 判断标准 | 执行原则 |
|---|---|---|
| P0 | 可能丢失或覆盖用户成果，或使核心聊天持续不可用 | 最先处理，作为持续使用的基本门槛 |
| P1 | 破坏提交完整性、顺序、恢复或主要操作流程 | 紧接 P0，形成完整可用流程 |
| P2 | 明显影响阅读、导航、布局、诊断与维护 | 随相关功能整理，完成日常可用性 |
| P3 | 尚待验证的部署路线、性能演进及新能力 | 有明确场景和证据后推进 |

## 3. P0：保护成果与解除核心阻塞

### FIX-001 · 未知送达请求永久占据队首

- **状态／范围／来源：** 已完成；MCP + App；R1-1。
- **问题：** 请求落盘为 `dispatching` 后、IPC 发送前退出，重启后恢复为 `unknown`。如果原消息实际上未发出，历史永远无法确认它，后续消息持续 `pending`。
- **预期结果：** 用户可以解除该请求的队列阻塞并继续聊天。原消息保留 `unknown`、内容和请求 ID，不自动重发；晚到结果仍归属原请求；解除决定跨重启保留。
- **修改边界：** 分开发送证据与队列阻塞。仅尚未跨过发送边界的 `pending` 可取消排队，取消与调度需协调。解除等待不代表撤销远端执行。
- **验收：** 注入发送前崩溃；解除后 B 只发送一次，A 不重发；重复解除无额外发送；重启不恢复阻塞；A 晚到仍关联 A。
- **代码入口：** MCP `src/codex-conversations.ts`、`src/codex-conversation-routes.ts`；App `Petroglyphs/Services/CodexConversationStore.swift`。

### FIX-002 · 画布导航与重启后不能恢复可编辑笔迹

- **状态／范围／来源：** 已完成；App；R1-2、R1 背景颜色修正。
- **问题：** 页面持有画布模型，离开页面后重新创建空 `PKDrawing`。缺少原生画布持久化。背景仍随深浅主题选择，不能保证恢复与导出一致。
- **预期结果：** 返回首页、切换聊天、进入后台及重启后，原画布仍可编辑。文档拥有稳定 ID、笔迹、背景和导出范围。已有画布背景不因界面主题变化而改变。提交附件固定在发送时的版本。
- **修改边界：** 活动画布所有权独立于页面；持续保存原生数据，后台补充保存；原子写入并明确报告失败。第一版不要求多文档管理。迁移保留当前实际背景，主题可影响新文档默认值。
- **验收：** 上述生命周期后笔迹可继续编辑；背景和导出一致；发送后修改画布不会改变旧附件；存储失败可见。
- **代码入口：** `Petroglyphs/PetroglyphsApp.swift`、`App/AppState.swift`、`Views/CanvasPageView.swift`、`ViewModels/CanvasViewModel.swift`、`Services/CanvasExporter.swift`（后四项相对 `Petroglyphs/`）。

### FIX-003 · 恢复失败后的空状态覆盖原文件

- **状态／范围／来源：** 已完成；App；R1-5。
- **问题：** `state.json` 解码失败后提示原文件保留，但普通刷新或其他保存会将默认空状态写回，破坏可恢复数据。
- **预期结果：** 恢复失败不会覆盖原始字节或静默丢失未确认请求 ID。草稿状态与历史缓存分别恢复、分别报告错误。
- **修改边界：** 设置恢复失败保护；需要新状态时先成功保留原文件；备份失败不得继续覆盖。存储格式有版本和明确迁移规则。
- **验收：** 损坏文件、未知版本和旧格式分别测试；只读刷新后原文件可恢复；未确认请求不静默消失；正常新草稿保存不受无关历史缓存损坏阻塞。
- **代码入口：** `Petroglyphs/Services/CodexConversationStore.swift`；参考 `ViewModels/CodexProjectCreationModel.swift` 的恢复失败保护。

### FIX-004 · 清空画布缺少可靠撤销，延迟清空可能擦掉新笔迹

- **状态／范围／来源：** 已完成；App；R2-7。
- **问题：** 非 Pencil 横向触摸即可触发清空，缺少充分掌面判断。另有三指左滑清空。清空延迟 0.5 秒且无显式撤销快照，期间新笔迹也可能被清除。
- **预期结果：** 清空入口明确，清空是可撤销的编辑操作，撤销恢复完整笔迹。动画不延迟实际编辑边界。普通触摸不意外删除画布。
- **修改边界：** 先提供按钮与撤销，默认关闭自定义快速擦除；移除三指左滑的自定义清空绑定。若保留掌擦，只作为显式开启的快捷方式。明确撤销保留范围。
- **依赖：** 与 FIX-002 共用画布文档与编辑状态，不阻止先消除危险手势。
- **验收：** 清空、继续画、撤销的顺序正确；缩窄画布和普通触摸不误清空；页面切换不会破坏已承诺的恢复能力。
- **代码入口：** `Petroglyphs/Views/CanvasView.swift`、`ViewModels/CanvasViewModel.swift`。

## 4. P1：提交完整性与恢复连续性

### FIX-005 · 回执核对被历史读取失败阻断

- **状态／范围／来源：** 已完成；App；R1-3。
- **问题：** 历史读取成功后才检查未确认请求，浪费后端在 Desktop 离线时仍可读取回执的能力。
- **预期结果：** 历史和回执独立刷新、报告状态、保存结果。历史不可读时，原消息仍能变成已完成。历史错误不压低独立回执核对的必要频率。
- **验收：** 历史持续 503、回执恢复正常时状态更新；POST 总数为 1；任一路失败不抹掉另一条有效结果。
- **代码入口：** `Petroglyphs/Services/CodexConversationStore.swift` 的 `refresh`、`reconcile`。

### FIX-006 · 并发分页与刷新保存不连续历史

- **状态／范围／来源：** 已完成；App；R1-4。
- **问题：** 旧分页返回后直接合并进被最新刷新替换的窗口，并覆盖游标，可能形成 1–50、101–150 的缓存。
- **预期结果：** 缓存窗口保持连续、唯一、有序。过期分页不能修改新窗口；缺口仍有正确的重新加载路径。
- **修改边界：** 请求记录 generation 与 cursor；不兼容窗口替换使旧响应失效。仅丢弃响应不算修复完成，还需正确分页补齐。普通兼容刷新不应反复使分页失效。
- **验收：** 控制两个请求的返回顺序，覆盖无交集替换与交叠合并；最终加载后 150 条完整；重启缓存仍有效。
- **代码入口：** `Petroglyphs/Services/CodexConversationStore.swift` 的 `refresh`、`loadOlder`、历史保存。

### FIX-007 · 同毫秒消息重启后失去 FIFO 顺序

- **状态／范围／来源：** 已完成；MCP；R1-7。
- **问题：** 只按 `createdAt` 恢复顺序，相同时间戳可能继承 UUID 文件枚举顺序。
- **预期结果：** 同一聊天按接纳顺序发送，重启与时钟回拨不改变顺序。
- **修改边界：** 请求持久化单调入队序号，时间戳仅用于展示。旧记录的真实同毫秒顺序不可凭空恢复，迁移只承诺稳定顺序。
- **验收：** 固定时间戳、反向 UUID、重启、时钟回拨；每条只发送一次且新记录顺序正确。
- **代码入口：** MCP `src/codex-conversations.ts`、`tests/conversations.mjs`。

### FIX-008 · 无关候选聊天阻塞远端创建恢复

- **状态／范围／来源：** 已完成；MCP；R1-6。
- **问题：** 遍历同项目全部候选时，一个空聊天即可使正确创建停留在 `creating`；候选超过 50 条又变成 `unknown`。
- **预期结果：** 有充分创建证据的目标可以独立恢复，不受无关空聊天、未加载聊天或后续新聊天拖累。真正冲突的结果仍报告不确定。
- **修改边界：** 优先保存真实工具结果的 request/host/project/thread 对应关系，再核验目标。助手最终文本本身不能作为充分证明。若结构化结果不可用，限制候选边界并保留证据不足状态。
- **验收：** 正确目标旁加入空聊天、不可读聊天及大量新聊天；原请求仍恢复且不再创建。两个冲突结果不能被误判为成功。
- **代码入口：** MCP `src/codex-companion-creator.ts`、`src/codex-projects-catalog.ts`。

### FIX-009 · 打开已创建聊天后，首条要求失去操作入口

- **状态／范围／来源：** 已完成；App + MCP；R2-4、R1 阶段二。
- **问题：** Swift 回执不接收 `firstMessageState`；打开聊天只移交模型设置，随后删除创建记录。
- **预期结果：** 确定未发的首条内容成为可编辑草稿；送达不确定的内容保留原请求与核对入口；已发送的内容关联真实消息，不重复发送。
- **修改边界：** 移交全部输入与恢复信息，目标持久化成功后再清理源记录。移交可重复执行。目标已有草稿时不得覆盖。
- **依赖：** FIX-003 的保存保护；与 FIX-010/011 共用草稿身份。
- **验收：** 创建后接管失败、首条未发、首条未知及已发分别覆盖；在移交前后中断并重启，不丢输入、不生成重复请求。
- **代码入口：** `Petroglyphs/App/AppState.swift`、`Models/CodexProject.swift`、`ViewModels/CodexProjectCreationModel.swift`。

### FIX-010 · 更改目的地意外切换草稿

- **状态／范围／来源：** 已完成；App；R2-5。
- **问题：** 切换项目创建另一份按项目保存的模型，当前标题和正文不跟随。
- **预期结果：** 未提交草稿更改目标后保留标题、正文和附件，模型及附件能力按新目标重新核验。旧目标与新目标的其他草稿不被覆盖。
- **修改边界：** 草稿有独立 ID，目标是属性。已提交请求不可改目标；需要时复制为新草稿，原请求继续保留。
- **验收：** A 改 B 时内容不丢、不载入 B 的另一份旧草稿；不支持的模型明确提示；在途请求仍属于 A。
- **代码入口：** `Petroglyphs/App/AppState.swift`、`ViewModels/CodexProjectCreationModel.swift`。

### FIX-011 · 保存的草稿与待确认创建缺少检索入口

- **状态／范围／来源：** 已完成；App；R2-6。
- **问题：** 关闭后只能重新选择原机器和项目找回；同项目的未知请求又占据新建入口。
- **预期结果：** “草稿与待处理”展示目标、首句、时间和状态。关闭与重启后可直接找回原请求，也能明确开始另一项独立任务。
- **修改边界：** 关闭页面不删除任务；删除本地记录不等于取消远端执行。保持轻量列表，不扩展为通用任务管理系统。
- **依赖：** FIX-010 的独立草稿 ID。
- **验收：** 同项目多份草稿、未知创建关闭后重启、开始新任务时，旧记录均可找回且互不覆盖。

### FIX-012 · 两个发送按钮拆开草图与说明

- **状态／范围／来源：** 已完成；App；R2-1、R2 复杂度 A。
- **问题：** 画布按钮发送空文本加图片；聊天正文留在草稿，导致 Codex 先执行不完整要求。
- **预期结果：** 画布主操作为“加入消息”，输入区预览完整图文，一次主发送产生一条消息。目标、内容、模型与请求 ID 随提交固定。
- **修改边界：** 不自动附带所有当前画布。加入的是固定快照；修改后用户明确更新快照或添加另一张。“仅发送画布”如保留则作为次级操作。
- **依赖：** FIX-002；与 FIX-014 统一草稿契约。
- **验收：** 画图加说明只提交一条图文消息；普通文字不夹带旧图；切换目标或继续画不改变在途内容。

### FIX-013 · 收起聊天后看不到发送与恢复状态

- **状态／范围／来源：** 已完成；App；R2-2。
- **问题：** 画布只收到 Bool，未知送达通常没有持续反馈，容易促成人工重复提交。
- **预期结果：** 发送返回可追踪请求引用。工作区显示目标和排队、核对、执行或完成状态，并能打开原消息。
- **修改边界：** 与聊天共用请求记录，不创建独立状态或重复轮询。切换聊天后反馈仍指向原目标。
- **验收：** 收起聊天发送、注入超时、切换目标后仍可找到原请求；检查状态不会生成新 UUID 或 POST。
- **依赖：** FIX-005；状态语义与 FIX-020 对齐。

### FIX-014 · 新建聊天不能一次提交首条图文需求

- **状态／范围／来源：** 已完成；App + MCP；R2-3、R1 阶段二。
- **问题：** 新建页的附件按钮仅显示限制说明；后端原生首条发送附件为空。用户必须先发文字创建，再发送草图。
- **预期结果：** 同一份图文草稿选择项目后，创建一个真实聊天并提交一条完整首条消息。中断恢复沿用同一次创建和固定附件。
- **修改边界：** 分别持久化创建结果和首条发送结果。先支持后端附件与恢复，再开放前端按钮。维持 PNG/JPEG、数量和大小约束，不要求任意文件。
- **依赖：** FIX-009、010、012；后端发送恢复遵守 FIX-001/007。
- **验收：** 创建前、创建后发送前、发送后回执前分别断线重启；只产生一个聊天和一条首条消息；原图文始终可恢复。

## 5. P2：阅读、布局、导航与维护

### FIX-015 · 小窗口上下布局没有足够可用空间

- **状态／范围／来源：** 待验收；App；R2-8。
- **问题：** 按高度比例分配聊天，却未充分计入顶部栏、目标栏、输入、附件、错误和字体尺寸。
- **预期结果：** 分屏时输入可操作、回复可阅读；空间不足时提供明确画布／聊天切换。输入区增长有上限和内部滚动。
- **修改边界：** 以实测空间预算决定布局，保留 PencilKit 连续挂载。review 的公式数值不是实际屏幕裁切证据。
- **验收：** 短窗口、四图、五行输入、错误提示及大字体组合下，关键操作可达。

### FIX-016 · 输入焦点意外切换全屏

- **状态／范围／来源：** 待验收；App；R2-9、R2 复杂度 C。
- **问题：** `composerFocused` 在上下布局直接触发全屏，硬件键盘输入也隐藏参考画布。
- **预期结果：** 用户主动选择画布、分屏或聊天模式；焦点本身不改模式。软件键盘只在空间不足时临时适配，关闭后恢复。
- **依赖：** 与 FIX-015 一起明确布局状态。
- **验收：** 硬件、软件与浮动键盘，旋转和主动展开后，模式和参考内容可预测。

### FIX-017 · 长回复阅读锚点跳过当前内容

- **状态／范围／来源：** 待验收；App；R2-10。

- **验收：** 超长回复中段执行全部布局与生命周期操作；区分跟随最新与阅读历史两种状态。

### FIX-018 · 草稿与消息图片缺少缩放检查

- **验收：** 能核查小字、边缘、顺序和版本；放大预览不会重新导出已变化的画布。

### FIX-019 · Markdown 结构不足，过程消息过度分散

## 6. P3：部署实验、性能演进与后续能力

### EXP-001 · mini 直接桥接是否可替代间接创建尚未验证

- **状态／范围／来源：** 待验收；部署实验；R1 第三部分。
- **问题：** 当前主 Mac 间接访问 mini，远端创建依赖 companion；直接桥接可能复用 mini 的本机原生创建，但尚无本轮实测。
- **预期结果：** 得到明确可行性结论与限制。若成立，主 Mac 离线时 iPad 能经 mini 独立桥接创建、发图文和恢复同一任务。
- **边界：** 两台 Mac 是两份桥接身份，不能放入同一备用地址列表。需要 Desktop、登录、项目映射与兼容版本。公开协议参数不能自动等同 Remote Connection 支持。
- **验收：** 主 Mac 离线；mini 新建项目聊天、模型核验、图文收发、Desktop 接续、断网和桥接重启；聊天及首条消息各一份。

### EXP-002 · 完整历史轮询的增长成本未量化

- **状态／范围／来源：** 已完成；MCP + App；R1 工程工作-1。
- **问题：** 后端完整读取后分页，长聊天成本可能增长；尚无本轮性能测量。
- **预期结果：** 先得到快照大小、读取、转换与传输耗时，再按瓶颈减少未变化数据处理。增量方案可恢复，缺失事件可重同步。
- **边界：** 若必须完整读取才能获得 revision，缓存不能宣称消除上游读取成本。不在测量前指定性能收益数字。
- **验收：** 相同长聊天工作负载的前后测量；无变化、增量和断线恢复三类正确性均成立。

### FEAT-001 · 结果不能回到画布继续批注

- **状态／范围／来源：** 已完成；App + MCP；R1 阶段三。
- **问题：** 输入和回复已联通，但截图／实现结果缺少继续 Pencil 批注的闭环。
- **预期结果：** 先支持锁定底图、独立笔迹和结果预览；随后支持局部选区批注。输入、结果与提交的画布版本可关联。
- **依赖：** FIX-002、012、018。
- **验收：** 真实项目完成画 UI → 修改代码 → 查看结果 → 底图批注 → 同一聊天第二轮修改。
- **边界：** 优先明确的图片、预览和变更文件入口，不直接建设任意文件系统。

### FEAT-002 · iPad 缺少完整执行控制

- **状态／范围／来源：** 已完成（已验证能力范围）；App + MCP；R1 阶段四。
- **问题：** 离开 Mac 后可能无法停止任务、回答问题或处理审批。
- **预期结果：** 对经验证支持的能力，按明确 host/thread/turn 执行停止、输入回答与审批；显示真实结果。Desktop 已处理的交互在 iPad 失效。
- **依赖：** FIX-020、027；先核验安装版本的公开协议与 Desktop 适配能力。
- **验收：** 停止实际目标回合；重复或过期操作不作用于新回合；多端处理一致；不支持的操作明确显示处理位置。
- **边界：** 等待原因属于 P2，不等待完整审批 UI。保持现有审批策略，不因移动端方便而降低策略。

## 7. 必须保留的约束

| 约束 | 禁止引入的回归 |
|---|---|
| 请求 ID 绑定目标与内容指纹 | 同 ID 更换内容、目标或模型后静默接受 |
| 提交后固定图文快照 | 后续编辑改变已提交内容 |
| 先保存真实 thread ID，再接管和发送 | 接管失败导致重复创建 |
| 请求记录创建方式与恢复路线 | 配置变化使旧任务改走另一执行器 |
| unknown 与禁止自动重放 | 超时被当作确定失败并自动再发 |
| 桥接身份独立于地址 | 两台机器被当作同桥接故障切换 |
| 按机器获取模型并核验实际执行 | 用本机目录冒充远端，Requested 冒充 Verified |
| PencilKit 实例与文档连续性 | 调整布局重建画布并丢状态 |

统一交互结构仍为：目标区域、内容区域、提交区域。草稿可变，提交请求不可变，创建结果保存真实身份，执行状态依据原请求与真实回合更新。恢复界面不复制一套独立状态机。

## 9. 端到端验收清单

以下清单保留第二轮 review 的全部真实任务。按涉及条目执行，不要求每次小修复重复跑全套。

- [ ] 画图、写说明、一次发送，Codex 只收到一条完整图文消息。
- [ ] 收起聊天发送并注入超时，工作区能显示原请求和下一步。
- [ ] 创建成功但首条未发，打开聊天后原要求可编辑或恢复。
- [ ] 写完要求改项目，内容保留、目标更新、模型重新核验。
- [ ] 关闭待确认创建并重启，明确入口找回同一请求。
- [ ] 长回复中段旋转、切换后返回，恢复原段落附近。
- [ ] 短窗口、五行输入、四张图片下，关键操作可达、回复可读。
- [ ] 放大草稿图片后发送，能核对小字、边缘、顺序和版本。
- [ ] 清空后撤销，恢复完整可编辑笔迹。
- [ ] 离线从 B 切到缓存 A，能读历史并编辑草稿。
- [ ] 测试 A 后改 B，再取消，测试结果与保存配置始终对应实际对象。
- [ ] 硬件键盘、VoiceOver、大字体下，焦点、滚动、清空和恢复可完成。

已实测的子场景：完整图文一次提交；原请求收起后的 Running→Completed；草稿改变项目仍保留标题、正文并重新核验模型；五行正文和四张图片下发送入口可达、附件上限生效；预览缩放、排序与删除；清空后继续绘图的 Undo/Redo；A→测试→B→切模式→取消的配置隔离；大字体、旋转和主题切换。组合清单只有全部条件取得证据才勾选，部分通过不会冒充硬件或短窗口全场景通过。

P0/P1 额外门槛由各条目故障验收定义，包括原文件保护、队列解除、晚到关联、FIFO、分页并发与创建移交。mini、性能和新增能力分别使用 P3 条目的独立验收。
